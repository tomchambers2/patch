# @patch/mobile

Android-only Expo app for Patch. Three bottom tabs (Chats, Voice,
Settings), Manager incoming-call UX via Android `ConnectionService`, Expo
push, voice-note + voice-call overlays.

iOS is explicitly out of scope (per `spec/15-design-mobile.md`).

## Tech stack

- Expo SDK 52, React Native 0.76, TypeScript strict + `noUncheckedIndexedAccess`.
- `expo-router` (file-system routing under `app/`).
- `zustand` for state (chatStore / presenceStore / voiceStore / uiStore).
- `react-native-mmkv` for credential + identity persistence.
- `expo-notifications` for the Expo push token + local notification channels (`patch_messages` + `patch_call`).
- `react-native-callkeep` + a small Expo config plugin for the Android
  `ConnectionService` (full-screen incoming-call UI for `patch_call`).
- `expo-av` for audio I/O (voice-note + voice-call). Spec allows falling
  back to `react-native-webrtc` if expo-av can't deliver raw PCM frames.
- `expo-camera` for QR pairing.
- `lucide-react-native` for icons (matches the web SVG set).

## First-time native bootstrap

The native `android/` project is generated by `expo prebuild`. **You must
run prebuild before `eas build`** — the config plugin in
`plugins/withConnectionService.js` injects ConnectionService and the
foreground audio service into `AndroidManifest.xml`.

```bash
cd apps/mobile
pnpm install
pnpm prebuild        # → expo prebuild --platform android --no-install
git add android      # commit the generated tree
```

## Build pipeline

| Goal                       | Command                                        |
| -------------------------- | ---------------------------------------------- |
| Dev (Metro)                | `pnpm --filter @patch/mobile dev`              |
| Run on a connected device  | `pnpm --filter @patch/mobile android`          |
| Internal preview APK       | `pnpm --filter @patch/mobile build:preview`    |
| Production AAB             | `pnpm --filter @patch/mobile build:production` |
| Static JS bundle (sanity)  | `pnpm --filter @patch/mobile build`            |
| Type-check                 | `pnpm --filter @patch/mobile typecheck`        |
| Lint                       | `pnpm --filter @patch/mobile lint`             |
| Tests (vitest, pure logic) | `pnpm --filter @patch/mobile test`             |

`build:preview` and `build:production` shell out to `eas build`. The
preview profile builds an APK distributed via EAS internal; the
production profile builds an AAB for the Play Store. No server address is
built in: the app learns where its server is from the pairing code it scans.

## Push (`google-services.json` + EAS credentials)

Two one-time, separate steps — neither is a server env var:

1. Drop the production Firebase config into
   `apps/mobile/google-services.json` **before** running `expo prebuild` or
   `eas build`. The path is wired in `app.config.ts`
   (`android.googleServicesFile`).

   ```bash
   mv ~/Downloads/google-services.json apps/mobile/google-services.json
   ```

   The file is **required** — if it's missing, `getExpoPushTokenAsync()`
   rejects, `initPush()` throws, and the user sees a banner. A clearly-
   labelled placeholder (`apps/mobile/google-services.json`) is committed
   for dev onboarding; replace it with the production project file before
   any release build. Production keys must NOT be committed.

2. Upload that same Firebase project's FCM V1 service-account key to the
   EAS project (`eas credentials`) — this is what lets Expo's push API
   actually deliver a push, and the server never sees or needs it.

## Voice token + audio WSS flow

1.  User taps the composer mic in a chat detail.
2.  `startVoiceCall(chatId)` → `POST /api/voice/token { chatId }` →
    server returns `{ sessionId, audioUrl, expiresAt }`.
3.  We request mic permission, set Android audio mode (duck other
    media), populate `voiceStore.activeSession`, and open
    `new WebSocket(audioUrl)` to the host's audio endpoint.
4.  The voice-call overlay reads the active session and renders the
    full-screen UI (timer, mute, end-call).
5.  `endVoiceCall()` closes the WSS and clears the session.

For voice notes the same `expo-av` Recording API captures the file; on
release we hand the resulting URI to the server's voice-note endpoint.

## QR pairing for new devices

1.  Fresh install lands on `/pair`. The screen requests camera
    permission, then opens `CameraView` with QR scanning.
2.  An already-linked surface shows a QR encoding
    `{ nonce: string, devicePublicKey?: string }`.
3.  On scan, we POST `{ nonce, devicePublicKey, clientType: 'surface-mobile' }`
    to `/api/auth/pair/complete`. The server returns a JWT + identity.
4.  We persist the JWT via MMKV (`saveCredential`) and replace into the
    Chats tab.

For tests / dev a `patch://?credential=<jwt>` deep link is accepted by
`bootstrap.ts → maybeAcceptDevCredential`.

## ConnectionService (Manager incoming-call)

1.  A push data message with `kind: 'call'` (or a live
    `chat.call_request` over WS) arrives.
2.  `lib/push.ts` (push listener) and the WS dispatcher both call
    `showIncomingCall(callId, chatId, callerLabel)` →
    `RNCallKeep.displayIncomingCall(uuid, chatId, label)`.
3.  Native UI: full-screen incoming-call card on the lock screen +
    heads-up while in another app.
4.  On `answerCall`: we emit `chat.call_response { decision: 'accept' }`
    over the WS and call `startVoiceCall(chatId)` to drop the user
    straight into the voice-call overlay.
5.  On `endCall`: we emit `chat.call_response { decision: 'decline' }`.
    The server reaper cleans up timed-out calls after 30 s.

The `withConnectionService` Expo plugin injects:

- `<service android:name="io.wazo.callkeep.VoiceConnectionService" …/>`
- `<service android:name="io.github.tomchambers2.patch.VoiceAudioService"
android:foregroundServiceType="microphone"/>`

…into `AndroidManifest.xml` during `expo prebuild`. **NO FALLBACK** — if
the plugin can't find `<application>`, prebuild throws.

## Manual test plan

See [`testing/manual.md`](./testing/manual.md). Covers
ConnectionService, push notifications, both voice overlays, QR
pairing, offline / reconnect, and Settings sub-screens. The
ConnectionService flows can't be automated reliably (lock screen +
system call UI) — exercise on a real device every release.

## Maestro

`maestro/flows/smoke.yml` covers cold launch, deep-link pairing, tab
navigation, opening the first chat, and sending a message.
`maestro/flows/dictation.yml` covers the composer mic — tap-to-start
listening, clear-to-cancel, tap-to-commit, transcribing, and settling
back to idle — with a screenshot at each state. Run from the repo root:

```bash
maestro test apps/mobile/maestro/flows/smoke.yml --env CRED=<JWT>
maestro test apps/mobile/maestro/flows/dictation.yml --env CRED=<JWT>
```
